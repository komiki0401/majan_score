# 雀録 / JANROKU

React + TypeScript + Viteの麻雀スコア管理アプリ。公開大会はアカウント作成・メール認証なしで誰でも閲覧・入力・修正できます。Supabaseへ保存し、Realtimeで各端末のランキング・順位グラフを更新します。

## 開発

ダッシュボード下部の「新しいグループの専用URLを作成」から、グループ名の入力・内容確認を経て独立した雀録と共有URLを作成できます。グループ内の大会・参加者・対局・全期間ランキングは他グループや従来の公開大会から分離します。利用開始には管理者による追加SQLの適用が必要です。[グループ共有の設計・設定手順](docs/group-sharing.md)と[適用するSQL](supabase/groups.sql)を参照してください。既存の大会・データ・公開APIは変更しません。SQL未適用の間は作成ボタンを無効にし、従来の雀録を維持します。

Windows PCへの移行とスマホからのCodex接続は[Windows開発引き継ぎ手順](docs/windows-local-development.md)を参照してください。

Node.js 24 / npm 11。

```sh
npm ci
npm run dev
npm test
npm run build
```

ローカルでクラウド接続先を指定する場合は `.env.example` を `.env.local` へコピーし、Project URLと公開用Publishable keyを設定します。Secret keyやservice_roleを使用しないでください。公開キーだけではSQL設定の代わりにはなりません。

## 公開共有の初期設定・旧バージョン移行

[Supabaseの設定手順](supabase/README.md)と[SQL全文](supabase/setup.sql)を参照してください。SQLは新規・旧バージョン共通で、既存データを削除しません。**既存大会はSQL Editorで公開対象に指定するまで非公開です。**

通常のGitHub Pages URLで大会一覧を直接表示するには、GitHub ActionsのRepository Variablesに `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` を設定して再デプロイしてください。設定画面で生成する共有URLを配る方法にも対応しています。

## 主な機能

- 大会一覧 → 選択するとスコア入力へ。大会・参加者・半荘・スコアを共有。
- 点数入力から順位・ウマ・オカ・累計ポイントを自動計算。ルールは変更可能で、過去の結果は記録時ルールを保持。
- 計算済みポイントの直接入力にも対応。ウマ・オカを再加算しません。
- 累計ランキング、日付切り替え、順位折れ線、個人成績、ユーモアのある「卓の実況」。
- 名前と半荘ポイントの一覧表、CSV出力、記録の編集・削除・復元。
- 同時編集は参加者・半荘・設定単位で差分適用。別の記録を上書きせず、同じ記録の競合を検出。
- リクエストID、同一日・卓・半荘番号で重複登録を防止。
- 大会削除は論理削除。変更履歴はサーバーで保存し、復元操作も履歴に残す。
- 日本語UI・スマホ操作・ダークモード。

初期ルールは25,000点持ち・30,000点返し、ウマ +20/+10/−10/−20、オカを1位へ。同点は該当順位の順位点を分配し、端数は小数第4位まで保持します。設定から変更できます。自由な順で参加者を選び、入力順優先の同点処理は画面の上から順に扱います。

アプリの初期画面はダッシュボードです。メニューはダッシュボード、大会一覧の順に表示します。クラウドのランキングは「直近の大会」を最初に表示し、「全大会・累計」とタブで切り替えられます。ダッシュボード・対局履歴・参加者・設定の上部にCSV出力とスコア入力ボタンは表示しません。スコア入力はメニューから開けます。直近の大会は最終対局日が最も新しい公開大会（同日の場合は更新日時順、対局前なら更新日時順）で、大会名を表示します。タブは左から「直近の大会」「全大会・累計」の順です。大会未選択時のスコア入力は直近の大会を開き、大会がなければ大会一覧へ案内します。直近タブからのスコア入力は表示中の大会を開きます。

全大会・累計では、公開中の全大会の参加者・保存済みスコアをまとめてランキング化します。同じ名前（前後の空白を除く）は同一人物として合算し、削除済み大会は除外します。入力・履歴・設定は選択中の大会が対象です。ローカル記録を開いた場合は端末内の成績を表示し、クラウドとの重複集計を避けます。

ダッシュボードの集計対象欄は表示せず、ランキング・個人成績・グラフ・統計・実況を全期間で集計します。対局履歴も日付で絞り込まず、選択した大会の全日付の記録を表示します。着順分布の横軸は各プレイヤー自身の対局回数（1回目・2回目…）です。不参加の半荘は数えず、確認欄にその回の順位と対局日を表示します。同じ回数でも対局日・卓は人によって異なります。全大会の取得に失敗した場合は部分的なランキングを表示せず、前回の完全な結果と再取得ボタンを表示します。

全大会集計は既存のRLS付き公開更新インデックスをページ取得し、大会一覧の100件上限に依存しません。変更通知・15秒ごとの再取得とバージョンキャッシュを使用します。SQLの再実行は不要で、既存の大会・参加者・スコアは変更しません。

## データと安全性

公開対象は誰でも編集できます。秘密情報や公開できない個人情報は登録しないでください。DB全体は公開せず、RLSと検証付きRPCで公開大会の操作だけを許可します。未公開大会・旧ユーザー情報・旧監査ログは匿名利用者に公開しません。匿名利用のレート制限とデータ量上限、公開運用の限界は設定手順書に記載しています。

旧ローカル記録は元のブラウザに保持し、公開大会へコピーできます。端末内保存では最新20件の全体バックアップを保存し、履歴からその時点に戻せます。ブラウザデータ削除でローカル記録・端末内履歴は消えるため、CSV出力もおすすめします。CSVは閲覧用で再インポートは未実装です。

## GitHub Pages

機能追加・修正は、`npm run verify`（自動テスト → 型チェック → ビルド → 公開前検証）が成功した後にcommit・mainへpushし、GitHub Actionsで自動公開します。毎回の公開承認は不要です。検証に失敗した場合はpush・公開を止め、Actions側で失敗した場合は新しい成果物をデプロイしません。運用ルールは [AGENTS.md](AGENTS.md) に保存しています。

公開前検証は、ソース・成果物へのSecret Key/秘密鍵の混入、実環境の匿名アクセス拒否、公開大会・通知・変更履歴の読み取りを確認します。実環境にはGETリクエストだけを送り、既存データ・SQL定義を変更しません。RLSフラグと両クライアントロールの更新・関数実行権限はPGliteの一時DBで検証します。本番の管理カタログを確認するものではありません。CIでは既存の2つのRepository Variablesを使用し、未設定・形式不正・アクセス検証失敗時は公開を停止します。`.env.local` と秘密鍵はcommitしません。

Settings → Pages → SourceをGitHub Actionsに設定します。main更新時にテスト・型チェック・本番ビルドを行い、成功後デプロイします。相対baseなのでリポジトリ配下に対応。HTTPSで利用してください。

参加者画面の「以前参加した人をすべて追加」は、公開中の全大会（ローカルでは端末の記録と保持中の変更履歴）に登録された名前を一括追加します。同名は重複せず、追加先の新しいIDを発行し、スコアはコピーしません。100人上限を超える場合は一括追加を行いません。クラウドは既存の検証付き差分APIでまとめて保存し、同時追加の競合も検出します。

卓の実況はトップの状況に加えて、中位の接戦、追い上げ、直近の半荘トップ、巻き返しへの応援を表示します。20秒ごとに自動で切り替わります。「次へ」ボタンは表示しません。最多トップ回数、直近の獲得ポイント、自身の対局での連続トップ、対局前の案内など、成績に応じた実況も表示します。

対局履歴は初期状態で「全大会」の全日付・全半荘を表示します。大会を選ぶとその大会だけをポイント一覧と詳細履歴に共通適用します。「集計対象」の日付選択欄は表示せず、期間は常に全期間です。各対局に元の大会名を表示し、編集・削除は元の大会と参加者IDで行います。変更履歴・復元の対象大会名も表示します。

スコア入力のフォーム上部には、入力先の大会名を大きく表示したカードを配置します。対局日・卓・半荘番号と共有大会／端末内の区別も表示し、「大会を変更」で一覧へ移れます。保存前の確認画面にも保存先の大会名を表示します。

スコア入力画面はページ見出し・説明文・上部アクション・大会の接続状態帯を表示せず、入力先の大会名カードとフォームから表示します。

スコア入力の大会は、入力先カードのプルダウンで切り替えられます。未保存の点数や編集内容がある場合は破棄を確認し、切り替え後は選択した大会の参加者・ルールで新しい半荘を入力します。対局履歴の名前・ポイント一覧は名前を縦、各半荘を横に配置し、順位と累計ポイントを表示します。登録順・ランキング順（累計ポイント降順）・累計ポイント昇順を選べます。同点は同順位で、未参加は「—」です。半荘見出しから元の大会の記録を編集できます。

ナビゲーションは「ダッシュボード・スコア入力・対局履歴・大会管理・設定」の順です。大会一覧と参加者管理は「大会管理」に統合し、大会ごとの「参加者を管理」ボタンまたは管理対象のプルダウンで対象大会を選択できます。

スコア入力画面は「新しい半荘」見出しと卓番号・半荘番号の入力欄を表示しません。新規記録は1卓として、選択した大会・対局日の次の半荘番号を自動設定します。既存記録の編集では元の卓・半荘番号を保持します。

大会管理の大会一覧は初期状態で折りたたみ、「大会一覧」を押すと表示します。大会カードは大会名編集・削除（削除済みは復元）を表示し、スコア入力・参加者管理・大会URLコピーのボタンは表示しません。大会名編集は既存の検証付き設定差分APIを使い、参加者・スコア・ルールを保持します。

グループ作成後は発行した専用URLをその場に表示し、コピーまたは「専用ページを開く」で利用を始められます。ブラウザの保存領域が使えない場合も、同じ画面内の再試行では同一リクエストを保持して重複作成を防ぎます。画面を閉じる前に発行したURLを保存してください。

折れ線グラフ（現在の表示は着順分布）はダッシュボードから対局履歴へ移動しました。対局履歴の大会選択をグラフ・ポイント表・履歴一覧で共通適用し、全期間を表示します。名前・ポイント一覧、着順分布のグラフ、対局履歴の順に表示し、プレイヤー別表示と従来の順位集計は維持します。スマホではグラフ幅を画面に合わせ、高さと選択ボタンの余白を調整しています。
