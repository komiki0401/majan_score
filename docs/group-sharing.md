# グループ専用URL共有

## 保存領域とアクセス制御

既存の public.jr_rooms と既存の公開APIは変更しません。グループは独立した jr_group_private スキーマに保存し、従来の公開大会には混ぜません。既存データの移動・コピー・更新・削除は行いません。

共有URLは同じGitHub PagesのURLに #group= と暗号学的乱数32バイト（256ビット）を付けます。グループ名や大会IDだけで取得することはできません。トークンはブラウザから x-janroku-group ヘッダーでAPIに送り、DBにはSHA-256ハッシュだけを保存します。URLのフラグメントはPagesのHTTPリクエストや通常のRefererに含まれません。ブラウザ履歴、同じページのJavaScript、画面共有、LINEへの転送などからは共有され得ます。

グループのテーブルすべてにRLSを有効化し、anon/authenticated/PUBLICからスキーマ・テーブル・内部関数の直接アクセスを取り消します。公開RPCだけが権限を持ち、全読み取り・保存でトークンを検証します。内部エンジンは現在のグループに限定した更新可能ビューを通し、WITH CASCADED CHECK OPTIONで別グループへのINSERT/UPDATEを防ぎます。共有リンクの権限は閲覧・入力・編集・論理削除・復元です。メンバー個別の本人確認・追放はありません。URL紛失時の自動復旧・URLの失効と再発行は今回未実装です。

グループごとに参加者・大会・対局履歴・ポイント・全期間集計・ランキング・変更履歴を分離します。同名参加者を合算する範囲もグループ内だけです。グループ切り替え時はReactツリーを作り直し、キャッシュ・入力途中の内容を引き継ぎません。端末内の旧記録への切り替え・コピーはグループ画面に表示しません。

Realtimeにグループの合言葉を渡す設計は避け、15秒ごとの取得・オンライン復帰時の再取得で同期します。公開用Publishable Keyだけを使用し、Secret Key・service_role・DBパスワードはフロントエンドにもActionsにも置きません。共有URLのトークンをログに出力しないでください。

## SQL適用（管理者が1回）

対象はこのリポジトリの supabase/groups.sql です。groups-header.sql/groups-footer.sql は生成用の断片なので単独実行しません。従来の setup.sql を再実行する必要はありません。

追加内容：専用スキーマ、6テーブル、グループ限定ビュー、内部の検証・差分更新関数、9個の公開RPC。既存オブジェクトには手を触れません。独立した内部エンジンには現在の検証・サーバー計算・競合検出・変更履歴・論理削除/復元を再利用します。グループ作成時だけ新しい空のグループと最初の大会を作ります。

1. 既存のSupabaseプロジェクトを選びます。別プロジェクトの作成は不要です。
2. SQL Editorで groups.sql の全文を確認・実行します。トランザクション内なので途中失敗時は全体を戻します。すでに存在するグループのデータも再適用で保持します。
3. jr_group_private はData APIの公開スキーマに追加しないでください。Realtime publicationにも追加しません。
4. ページを再読み込みします。APIの準備が確認できると「新しい雀録を作成」が有効になります。

この作業は公開RPCの追加を含むDB設定変更です。実施する前に変更内容をレビューしてください。現在のセッションにはSupabaseの管理接続がなく、Codexから本番への適用はしていません。

## 検証と運用

npm run verify は生成SQLの整合性、PGlite上の既存・グループデータの分離、トークンなし・誤トークン・他グループIDによる不正取得/更新の拒否、再送重複防止、RLS/ACL、UI回帰、型チェック、ビルド、実環境の読み取り専用検証を実行します。本番にテストグループやスコアを登録しません。SQL未適用の場合は従来の機能を維持し、グループ作成は準備中として無効にします。SQL適用済みの場合はトークンなし・不明トークンのグループ情報取得が拒否されることも公開前に検証します。

新規グループは全体で毎分3件・UTC日次100件までです。大会作成・保存も既存と同等の全体レート制限があります。サービス利用者別の上限ではなく、荒らしで通常利用も制限される可能性があります。Supabaseの転送量・DB容量・使用量アラートを確認してください。必要ならEdge FunctionでのIP別制限やCAPTCHA等を別途導入します。

通常のコード変更は検証成功後にmainへ反映してPagesで自動公開します。追加SQLはGitHub Actionsから自動実行しません。SQLのソースは groups-header.sql・既存setup.sqlの関数定義・groups-footer.sql で、npm run groups:sql から単一ファイルを再生成します。ソース更新時は生成SQLと権限を再レビューしてください。

## 作成導線

通常の大会・ランキング・スコア入力を優先し、グループ作成はダッシュボード下部に控えめに表示します。「新しいグループの専用URLを作成」→グループ名入力→作成内容の確認→「この内容でグループを作成」の順で進み、最終ボタンまではAPIへ作成を送信しません。既存グループの共有URL表示は引き続き専用ページの上部に表示します。
